# 可用于简历的项目经历

**RepoAudit-Agent｜开源框架工程约束核查与多仓选型工作台**
技术栈：Python 3.11、FastAPI、Pydantic v2、HTTPX、SQLite WAL、OpenAI Responses / Function Calling、SSE、原生 JavaScript、GitHub Actions。

- 面向开源框架引入时环境约束分散、文档声明与实现难核对的问题，打通热门发现、1～3 仓候选比较、逐项判断、源码溯源和多轮追问，并提供可离线展示的真实录制回放。
- 实现 Lead 需求拆解与单仓 Sub 独立上下文，构建概览、索引、切片、依赖、部署和 Issue 六类只读工具；采用渐进式读取、当前上下文区间去重及外置证据存储，控制每轮模型和工具预算。
- 基于固定 commit、原始行号和 SHA-256 构建证据链，校验会话归属、跨仓引用和逐字摘录，对无效引用降级；基于 SQLite WAL、执行租约与工具回执实现检查点恢复及历史追问。
- 使用 SSE 驱动统一工作台，支持决策矩阵、证据抽屉、报告轮次和 Markdown/Replay 导出；通过 94 项 Python、13 项前端测试及进程退出恢复测试，形成 16 例冻结契约、真实模型评测报告和 3 份真实仓库回放。

## 面试时可展开的事实

- 真实双仓案例：Python 3.10 条件下，固定版本的 Pydantic AI 声明不满足、Agno 满足；追问升级至 3.11 后两仓满足。两轮固定相同版本，追问的 4 次工具均命中缓存。
- 验收发现并修复的工程问题：SSE 终态与在途请求竞态、失效租约恢复入口、跨仓比较错误下放给单仓上下文、追问后历史报告不可切换。
- 实际评测：最终首轮 11/13 满足标签与证据契约，含 1 例网络中断和 1 例缺证据标签错误；中断案例通过检查点恢复完成，原始失败记录保留。
- 取舍：小样本多轮编排总 tokens 高于全文单轮基线，因此不写降本百分比；当前按仓顺序执行，以单机可运行、可恢复、可审查为交付目标。
