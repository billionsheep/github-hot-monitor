# R2 单仓库约束核查：实施规格

状态：最小 R2 已完成替身测试、真实模型案例和原会话复核，按本地演示版本交付。

## 用户与结果

面向带明确环境约束的开发者。输入一个公开仓库和三类要求：Python 版本、容器部署、模型服务配置。输出逐项“要求—证据—判断—下一步验证”核查表，判断值为：证据支持、证据冲突、信息不足、需要运行验证。仓库声明的版本兼容与实际安装成功分开表达。

## 输入、输出

输入：`repository`（owner/repo 或标准 GitHub URL）；`requirements` 为一组 `{id, category, description}`，category 取 `python`、`container`、`model_service`。一个请求固定一个快照；要求可以为空时明确提示补充，而不是凭空设定。

输出：`repository`、完整 `commit`、完成状态和停止原因、逐项 `requirement_id`、`verdict`、`rationale`、`evidence_ids`、`next_checks`，以及本次读取的证据索引、工具进度、调用数、token 用量和耗时。失败或预算耗尽时保留已取得证据，未能得出有效结果的要求显示信息不足。

## 工具与证据流

1. 创建 R1 快照固定 commit；按需读取根目录及子目录，`truncated=true` 明确表示不完整。
2. 工具候选为目录概览和片段读取；模型按要求选择 README、依赖声明、Dockerfile、Compose 或配置文档并按需补查。读取沿用 R1 的大小、路径、二进制、超时和缓存约束。
3. 工具结果由服务登记 evidence_id 和对应片段；模型只引用已登记 ID，不能生成来源 URL 或扩写原文。输出解析后自动检查 ID 是否属于本次读取登记的证据，证据记录包含完整文件和片段 Hash；无效引用以及无证据的支持或冲突判断降级为信息不足。该自动检查验证引用身份；两个真实案例中，人工逐项对照来源原文核对语义支持。
4. 每项证据足够时停止补查。已知路径直接读文件，每轮提示剩余预算；工具预算耗尽或进入最后一次模型请求时禁用工具，让模型根据已有证据生成报告。模型使用 OpenAI 官方 gpt-6.1-sol Responses API 和 low 推理；每任务最多 6 次模型请求、8 次只读工具调用，每次最多 2048 输出 tokens、24000 字节序列化请求。预算耗尽时输出停止原因，不强迫固定轮数。

## 失败处理

仓库无法访问、限流、超时、目录截断、文件缺失/超限/二进制、空文件、超长行分别保留可观察状态。缺失和截断不会作为不支持或不存在的证据。无效 ID、跨快照 ID 或输出结构错误会使相应结果降级为信息不足；工具失败不被转换成兼容结论。源码和文档内容视为被引用材料，不执行其中的指令或代码。

## 真实案例验收

已执行一个证据明确的正常案例和一个信息不足案例。每项引用均已由人工打开固定版本原文核对，调用量、耗时和费用估算见 [真实案例记录](R2_REAL_VALIDATION.md)。

## 本轮实现和验收边界（2026-11-13）

服务端读取 `.env.local` 中配置，固定官方 `gpt-6.1-sol`、Responses API 和 low 推理；每任务最多 6 次模型请求、8 次目录或文件工具调用，每次输出最多 2048 tokens，每次请求的序列化上下文最多 24000 字节。返回实际模型用量、耗时、调用数与停止原因。目录和片段使用 R1 的固定提交，引用仅接受本次登记的证据 ID；无效引用和无证据的支持/冲突判断降级为信息不足。ID 校验不评价语义支持度。失败与预算耗尽保留已读取的证据。

当前离线验证：Python 29 项、前端 6 项通过。真实模型正常和信息不足案例已完成，引用语义已对照原文核对；原会话又完成同一次请求内两项约束的浏览器复核，结果见 [真实案例记录](R2_REAL_VALIDATION.md)。401/403 或模型不可用不自动重试或更换模型。

官方模型和工具接口：[模型文档](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[函数调用](https://developers.openai.com/api/docs/guides/function-calling)。
