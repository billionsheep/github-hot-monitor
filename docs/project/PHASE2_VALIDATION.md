# RepoAudit Phase 2 实施与验证记录

日期：2026-11-13（Asia/Shanghai）。状态：Phase 2 已通过主会话独立验收，包含冻结样本、故障恢复和一次真实模型核查；具体条件及用量如下。

## 交付与边界

- `harness_schemas.py` 定义核查项、引用、结论、会话输入和可配置预算；`guardrails.py` 校验会话关联、仓库、提交、证据身份、原始片段/文件哈希、摘录和正文引用一致性。任何无效引用会将受影响行降级为 `UNVERIFIED`。
- `agent_harness.py` 实现 Lead 共用核查项、逐仓独立上下文、六种只读工具、受限模型视图及 Lead 汇总。所有工具结果（包括 `facts`）均作为不可信文本转义封装。完整产物在本地存储；模型只收到有界索引、事实和短摘录，并看到省略提示。被省略原文不计入上下文已读范围。
- `harness_store.py` 使用数据库版本 4：租约与版本检查、持久化状态、模型用量、工具轨迹、事件和报告版本。Phase 1 已预存的不可变证据可以先缓存；工具结果、会话证据关联、轨迹、事件、receipt 和 checkpoint 的完成状态在同一事务提交。工具轨迹记录参数、耗时、状态及产物 ID。
- 六工具仍由绑定的 `repo + commit` 调用；重复片段按 `context_id` 记录，部分重叠仅补缺口。依赖/部署结果中实际注入的完整文件片段也参与去重。新仓库和追问使用新上下文；全局缓存的大纲不等于当前模型已看到大纲。追问传入上一版问题、核查项、该仓库已校验短结论及证据索引，原文需按需重新读取。
- 默认每仓最多 6 次模型请求、8 次工具调用；Lead 最多 2 次。每轮还限制最多 20 次模型请求、24 次工具调用、60000 输入预算、16384 输出预算，单次输出预留 2048 tokens，序列化请求最多 24000 字节。预算可在创建会话时调低；累计会话 usage 与当前轮预算分别保存。输入预留按请求 UTF-8 字节数保守计入；实际用量以响应 usage 为准。失败与未知请求也占调用次数，未知请求保留预留量。
- 租约默认约 180 秒，每 30 秒续租；单次只读工具或大纲前置查询超时上限 120 秒。进程退出后没有启动时的死进程识别：须等旧租约到期，查询可见 `lease_busy` / `retry_after`，提前恢复返回 409。已提交步骤不会重跑。模型请求已发送但响应尚未持久化时记 `UNKNOWN`，恢复可能再次请求，不能保证跨外部 API 恰好一次或零重复计费。收到明确 HTTP 拒绝时记 `REJECTED`，不计为未知。

引用身份与哈希检查只证明引用和摘录可追溯，不能证明判断的语义支持；工具能力边界和结论是否受恶意内容诱导分别验证。
