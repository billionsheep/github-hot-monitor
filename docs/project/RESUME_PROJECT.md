# 简历项目经历

## 可直接使用的版本

**GitHub Hot Monitor｜开源项目工程约束核查 Agent**  
**技术栈：**Python 3.11、FastAPI、Pydantic、SQLite、OpenAI Responses API / Function Calling、JavaScript、GitHub Actions

- 面向开源项目选型时文档分散、环境约束难核实的问题，在 GitHub 项目监控工具基础上实现单仓库核查 Agent，将 Python 版本、容器部署和模型服务要求转为带证据引用的逐项核查结果。
- 设计模型工具调用循环，通过目录查询与文本片段读取完成“识别证据缺口—选择文件—补充证据—生成报告”；使用 Pydantic 与 JSON Schema 约束输入输出，支持证据支持、证据冲突、信息不足和需要运行验证四类判断。
- 实现固定 commit 的证据读取与 SQLite 缓存，保留文件路径、原始行号、SHA-256 和来源链接；校验引用是否属于本次读取，对无效引用降级处理，并限制文件大小、读取范围与模型调用预算。
- 完成本地网页演示及 29 项 Python、6 项前端自动化测试，使用真实模型验证正常核查与信息不足场景，支持查看工具进度、引用来源、token 用量和耗时。

## 面试时如何说明价值

**解决的问题：**选择开源项目时，需要在 README、依赖声明和部署配置间反复查找，且容易把仓库声明当成已经运行验证的结果。本项目把明确要求和固定版本证据组织成可复核的判断表，便于决定下一步安装、部署或补查什么。

**Agent 如何工作：**模型根据要求选择只读工具，读取结果回到上下文，再决定补查或结束。目录和文件读取始终绑定同一个提交；模型生成的引用必须能在本次证据登记中找到。

**实现中的取舍：**复用原生页面与 SQLite，先完成本地单仓库闭环；保留明确的调用上限和信息不足状态。引用 ID、行号与 Hash 检查来源身份，语义支持在演示验收时逐项对照原文核对。

**演示入口：**按 [运行说明](RUNBOOK.md) 启动，使用 [两分钟脚本](R2_DEMO.md)；真实用量和结果见 [验证记录](R2_REAL_VALIDATION.md)。
