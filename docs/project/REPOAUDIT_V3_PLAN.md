基线：1042a9b / repoaudit-demo-2026-11-13。状态：实施中。用户已授权按 V3-1 至 V3-4 依次交付、独立复核及本地提交；保留 v2 标签与三份原回放，不自动推送。

## 交付目标

交付架构研报（arch_research）、安全线索审计（sec_sentinel）、部署适配（deploy_readiness）三个工作流。每条完成输入、取证、报告、原文、追问/导出、静态回放。

沿用 Python 3.11、FastAPI、Pydantic、HTTPX、SQLite WAL 和原生网页。多仓顺序执行；Python AST 深度分析，JS/TS、Shell、文档标明规则线索。统计标注扫描范围，不生成含金量分数。

## V3-1：完整取证与两个工具

- AST 索引记录参数、默认值是否存在、关键调用/关键字和完整语句行号；get_markdown_outline 增加可选 symbol_or_param_hint，优先匹配 base_url、endpoint 等。保留旧工具调用兼容。
- analyze_architecture_profile：入口/路由、执行循环、状态持久化、并发重试、模型工具协议；区分导入和具体实现。结构化图谱每条边绑定文件证据，标明调用、导入、读写。
- scan_security_and_risk_sinks：all、exec_sinks、env_and_network、prompt_injection；分规则命中、上下文复核、证据不足。上下各 20 行并扩展完整语句；进程调用、环境变量、URL 本身不等于漏洞。协议名称不直接等于违规。
- 共用扫描器：repo 内 path_prefix；最多 24 目录、24 文本文件、1 MiB 总读取、512 KiB 单文件；排除缓存/生成目录。超限、解析失败、目录截断明确覆盖缺口和继续位置。
- arch_profile/security_scan 派生产物含规则版本、范围、哈希、底层引用；后端及浏览器均可校验。

验收：跨行和别名调用完整定位、解析失败/超限范围准确、线索能打开固定版本原文。
