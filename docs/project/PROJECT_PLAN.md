# 开源 Agent 项目工程约束核查助手

## 定位与判断规则

围绕 Python 版本要求、容器部署方式、模型服务配置提供可追溯的逐项核查。报告区分：证据支持、证据冲突、信息不足、需要运行验证。引用 ID 与 Hash 校验验证来源完整性，结论是否由原文支持单独评估。证据充分即停止，不按调用轮数证明能力；收益指标实测后填写。

## 阶段

- R0：已有静态榜单本地基线完成，历史验证见 README。
- R1.1：三项修复及阅读/接口完善完成本地验证，R2 准备规格已写，等待原会话独立复核。
- R2：单仓库模型工具调用、按需补查和结构化核查报告；届时确定运行时 API 与预算。
- R3：固定案例评测、引用支持度与误报率、实时演示和离线回放。
- R4：多仓库发现与比较；成熟项目检索在本阶段加入。多 Agent、向量检索与框架根据实测需要引入。

## R1 实施合同

技术栈：Python 3.11、FastAPI、Pydantic、SQLite、现有原生网页。

1. 修复焦点卡片专项分显示，增加前端验证，在发布流程中运行现有测试。
2. 接受公开 GitHub owner/repo 或标准仓库 URL；创建快照时固定默认分支 commit SHA，后续树与文件都使用同一 SHA。
3. 提供创建快照、查询目录、读取文本片段三个接口；默认显示 README，允许选择依赖声明、Dockerfile、Compose 等文件。
4. 证据卡记录仓库、commit SHA、路径、原始行号、抓取时间、内容 Hash、固定版本来源链接。保留原文与行号，不以清洗后的文本冒充原文。
5. SQLite 持久化快照与缓存，运行数据排除 Git；相同版本重复读取命中缓存。
6. 限制当前仓库文本读取，拒绝路径穿越、其他仓库 URL、二进制。文件上限 512 KiB，单次片段最多 200 行、16 KiB，截断明确提示。
7. 树截断明确为不完整，支持按目录继续浏览；不得据此判定文件不存在。
8. 请求有超时、有限重试和限流响应处理；凭证只在服务端环境变量，不输出敏感值。
9. FastAPI 本地同源提供页面和 API；保留静态榜单和 Pages 构建。首轮不接模型、不读 Issue、不执行仓库代码、不公开部署。

## 验收

- 原有六项测试通过，榜单搜索与切换正常，专项分显示正确。
- 公开仓库完成输入、固定版本、目录、片段、证据卡全链路；重复读取命中缓存。
- 链接与原始行号一致；HTML 内容作为文本安全展示。
- 仓库不存在、README 缺失、限流、超时、目录截断、二进制、超限文件和非法路径有测试与明确结果。
- 浏览器实际验证输入、选择文件、展开证据、打开来源。
- 同步运行与学习说明，记录输入输出、关键模块、缓存命中/失败走读、一个修改练习及复现命令。

## R1.1 实施合同（2026-11-13）

目标：稳定证据读取体验与接口，为模型核查提供明确证据契约。复用此前实施会话与当前 checkout，本轮完成以下工作后停止在 R2 准备状态。

### 三项验收问题修复

1. 仓库 A 成功后切换 B，B 树请求失败会显示 A 旧目录、B 标题，旧按钮向 B 发请求并卡住。新提交立即清空旧目录/卡片；请求及事件绑定各自快照；晚到响应不得影响新快照；提供明确重试。
2. 静态站点没有 API 却展示可提交的读取入口，HTML 错误被当作 JSON 解析。增加能力检测或构建模式区分，静态模式禁用实时读取并解释本地服务入口；统一处理非 JSON 错误、网络错误与服务不可用，保留榜单。
3. 空文件返回 start_line=1/end_line=0。定义明确 empty 状态和无行号表示，不显示倒置范围；空文件来源链接不附虚构行号。

### 证据阅读与接口

- 原文逐行显示原始行号，保持 textContent 安全文本渲染；当前文件高亮、目录面包屑。
- 支持上一段/下一段（按实际访问历史返回，不猜测字节截断页长）、指定起始行；超长单行明确提示并链接完整来源。
- 根据已读取目录提供 README、Python 依赖声明、Dockerfile、Compose 常用文件入口，不把尚未读取目录解释为缺失。
- commit 与 Hash 缩略显示，可复制完整值；保留来源链接、抓取时间、缓存状态。
- 为快照、目录、片段和应用错误提供明确 Pydantic 响应契约，现有路由继续可用。
- 稳定 evidence_id 由仓库、commit、路径、原始范围、partial_line 与片段 Hash 等内容身份确定，不包含抓取时间或随机快照 ID；相同片段重复读取 ID 一致，不同范围/版本不同。
- 保留完整文件 SHA-256，新增片段 SHA-256；空文件仍有稳定身份。

### 验收与学习

新增回归覆盖 A→B 失败、跨仓库晚到响应、静态模式/非 JSON、空文件、证据 ID 稳定性、完整/截断分页与原始行号、HTML 文本渲染。运行现有测试和相应新测试；浏览器验证本地实时模式与静态模式。同步 README、CODE_GUIDE、RUNBOOK，记录实际结果，不沿用旧测试数量作当前结果。

## R2 准备规格（本轮只准备，不接模型）

核心用户：带明确环境约束的开发者。输入单个公开仓库与 Python 版本要求、容器部署要求、模型服务配置要求；输出“要求—证据—判断—下一步验证”的核查表。

判断采用证据支持/证据冲突/信息不足/需要运行验证；声明兼容与实际安装成功分开。工具候选是概览/目录、片段读取，按需补查并在证据充分或预算耗尽时结束，不强制多轮。模型只输出结构化引用，不自行制造来源；证据 ID 存在与语义支持分别验证。

R1.1 完成时提供下一阶段最小任务、输入输出草案、工具契约映射、失败处理与小型评测案例建议；模型 API 渠道及预算仍待确定。不得在本轮调用收费模型、做自动代码执行、开展多仓库/Multi-Agent 或公开部署。

后续价值扩展：同约束多仓库比较、版本变化再核查、历史报告复用；隔离运行验证另行设计。简历依据真实实现、设计取舍、测试和评测逐步整理，不把 R1 文件读取直接写成已完成 Agent/RAG 平台。
